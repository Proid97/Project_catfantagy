# 대화 맥락

갱신일: 2026-10-21 · 한국 시간

4단계 세로 전환과 판 만들기를 배포했고, 교환소·안개·주사위 연출과 새 2D 지도 그림까지 올렸습니다. 2026-10-19에 덱 방식을 **종족 선택 + 종족 덱 + 함께 쓰는 필드 덱**으로 바꿨습니다. 다음은 **5단계 게임 시작**입니다. 게임 플레이와 밸런스 시험은 아직 하지 않았습니다. 현재 규칙은 [게임 설계](game-design.md), 작성 방법은 [작업 지침](../AGENTS.md)을 따릅니다.

## 결정의 흐름

| 순서 | 결정과 이유 |
|---|---|
| 출발 | 카탄의 주사위 자원 수급, 스타크래프트처럼 자원을 써 건물·유닛 배치, 무작위 카드 드로우를 결합하고자 함 |
| 콘셉트 탐색 | 냉장고·꿈·축제·고양이 등 여러 테마를 검토. 대중적으로 이해하기 쉬운 고양이 방향을 선호 |
| 최종 방향 | 동네 고양이에서 클래식 판타지 ‘냥국’으로 변경. 가칭은 운빨냥국배틀 |
| 운의 역할 | 시작 땅까지 안개로 가림. 주사위 수입과 카드 드로우에서 생기는 큰 운을 주요 재미로 삼음 |
| 클래스 | 냥전사·냥법사·냥살자가 서로 카운터가 되도록 설계. 은신 기습·높은 체력과 도발·넓은 공격 범위로 차별화 |
| 기본 판 | 육각 타일, 꼭짓점 건물, 변 위 길로 구체화. 모든 건물에 주변 타일 수급권 부여 |
| 행동 | 이동과 공격은 각각 턴당 1회, 스킬은 해당 유닛의 한 턴을 사용. 마나는 별도로 소모 |
| 공성 | 일반 건물은 두 번 피격하면 파괴. 왕성은 체력과 자동공격을 갖고 주변 정상 지원 건물에 따라 공격력이 바뀜 |
| 문서화 | 사용자가 남은 사항에 권장안 적용을 요청. 채택한 규칙과 새로 메운 임시 판정을 구분해 최초 기록 |
| 제작·관리 | 아트는 ChatGPT 이미지젠. 쉬운 한국어, 짧은 구성, 지속 가능한 파일명, 같은 분류는 같은 문서에서 갱신 |
| 아트 방식 | 피규어·종이 스탠드·토큰 모크업을 비교한 뒤 토큰 선택. 팔다리 애니메이션 없이 말 전체를 코드로 움직이고 마법 효과도 코드·이미지로 처리 |
| 디자인 상태 | 플레이 화면의 세부 디자인은 추후 변경. 캐릭터는 색·실루엣·자세를 다르게 수정한 세 이미지를 메인 콘셉트로 선택 |
| 메인 콘셉트 | 냥살자, 주황·금색 전사냥, 흰색·보라색 법사냥. 법사냥은 마지막 수정 과정의 세 번째 이미지. 경로와 미리보기는 게임 설계서에서 관리 |
| 대전 방식 | 한 기기를 돌려 쓰는 1대1 시험에서 각자 기기로 하는 봇·유저 대전으로 바로잡음. 프로토타입은 봇전 위주. 턴제 스타크래프트 + 카탄식 수급 + 카드 배치 운이라는 한 줄 구상과 화면 배치·조작 구상을 설계서에 기록 |
| 판과 모드 | 3단계 판(61칸)이 작아 이동력 2인 유닛이 너무 유리했음. 문명(넓은 판) + 카탄(수급) + 스타크래프트(종족과 전투)를 섞으려고 넓은 대륙, 귀한 자원, 험지와 지나갈 수 없는 땅을 권장안으로 채택. 최대 4인: 1대1·4인 개인전·2대2 팀전 |
| 시작 자리 | 시작 자리를 무작위로 정하되 너무 가까운 시작과 자원 없는 시작만 막음. 처음에는 시작 순서 주사위도 없앴으나, 같은 날 화면 흐름을 정하며 "각자 굴려 순서 자동 결정" 연출로 다시 넣음 |
| 덱 구성 | 2026-10-18에는 세 종족 카드로 덱을 직접 짜고 같은 종족 조합에 효과를 주기로 함. 2026-10-19에 되돌림: 60장 중 20장을 고르는 일이 막막하고, 손에 쓸 카드가 없는 판이 생기며, 덱 조합이 너무 많아 밸런스를 맞추기 어려움. 팩 두 개 섞기도 검토했으나 사용자가 종족 선택 + 종족 고정 덱(유닛·건물) + 모두 함께 쓰는 필드 덱(마법·함정)을 제안해 채택. 유닛·건물은 늘 내 덱에서 나와 손이 덜 막히고, 운은 필드 카드와 반반 뽑기가 맡음. 좋은 필드 카드를 남이 먼저 가져가는 긴장 때문에 함께 쓰는 더미로 정함. 시작 손패도 완전 무작위. 카드 색은 마법 파랑, 함정 빨강, 종족 색(냥살자는 검정으로 바꿈) |
| 카드 수치 | 2026-10-20 사용자가 냥전사·냥법사 카드를 직접 고침: 설명 글, 공격 범위 숫자, 타워 체력, 도발을 냥장군으로 옮김, 냥기사 9·냥장군 15 비용. 이 비용을 기준으로 세 종족을 기본 2~3·정예 9·전설 15 단계에 맞춤. 조정 이유: 기본 공격 피해는 1로 맞춤(단검냥 2→1, 숨어서 치면 +2). 막는 효과는 "다음 내 턴 시작까지"로 바꿈("이번 턴"이면 상대 턴 공격을 못 막음). 큰 범위 피해는 미리 보이게 함(별똥별은 다음 턴에 떨어짐). 막기 어려운 효과는 줄임(마나샘 3칸→2칸, 결계는 둘→하나). 피해 줄이기는 가장 큰 것 하나만 |
| 종족 역할 | 2026-10-20 사용자 결정: 냥법사 원거리 화력, 냥전사 균형과 체력, 냥살자 유틸과 전략. 모든 냥살자가 숨으면 불공평해 은신은 카드에 적힌 유닛만 하고, 나머지는 이동·공격하면 풀리는 위장으로 숨음. 안 보이다 먼저 치는 사기 종족이 아니라, 매복했다가 다가오는 적을 암살하는 예측 전략을 유도하려는 것. 튼튼한 방패는 체력 피해 디버프(독·함정 피해)만 막음 |
| 플레이어 색 | 처음엔 종족 색을 프로필에도 썼으나, 4인이 같은 종족을 고를 수 있어 구분이 안 됨. 2026-10-20 사용자 결정으로 판 위 말과 인게임 프로필은 플레이어 색(빨강·초록·파랑·노랑), 종족 색은 카드에만 |
| 카드·지형 그림 | 카드 그림을 판 위 말과 같이 쓰려 했으나, 사용자가 작가 그림 같은 작품성과 이야기를 원해 카드는 장면 그림, 판 위 말은 단순한 토큰으로 나눔. 참고 그림은 저작권 그림이라 생성에 넣지 않고 분위기(따뜻한 빛 하나와 차가운 바탕, 앞쪽 실루엣, 한 순간)만 글로 옮김. 자원 오브젝트는 건물·유닛과 겹쳐 읽기 어려워 칸 그림에 그려 넣기로 함. 2026-10-21 냥전사 장면 그림 다섯 장이 우리 인디 감성 대신 애니메이션 감성이 되어, 유닛은 원조 3인방 감성의 역동적인 게임 캐릭터 그림(배경 투명)으로 바꾸고 카드와 판 위 말에 함께 쓰기로 함 |
| 원본 그림 | 외곽선이 거칠다는 피드백. 원인은 우리 정리 단계가 아니라, 지휘 쪽 요청문의 "알파 0 또는 255" 조건 때문에 디자이너가 가장자리를 잘라 낸 것. 사용자 결정으로 후처리를 모두 빼고 생성 원본을 쓰며, 문제는 생성 단계에서 검수해 고침 |
| 교환소 | 카드 목록을 보다 떠올린 카탄식 항구. 교환 짝 여섯 가지를 해안에 하나씩 무작위로 두고, 교환소와 숫자 6·8 칸은 안개 없이 공개해 경쟁을 만듦(처음엔 6만 말했으나 8도 같은 확률이라 함께 공개로 정함). 쓰는 자리·비율은 권장안(변의 두 꼭짓점, 2:1, 기본 4:1)을 채택 |
| 안개 | 칸을 통째로 덮는 안개 대신 스타크래프트처럼 바닥은 보이고 오브젝트·숫자만 가리는 볼류메트릭 안개. 모름·앎·봄 세 단계로 정리해 교환소·6·8 칸 공개 규칙과 맞춤. 마을은 꼭짓점에 붙은 칸, 길은 변을 사이에 둔 두 칸을 봄. 처음엔 흰 연보라였으나 내 위치·성에 집중되게 짙은 회색으로 바꾸고 바다·미니맵까지 덮음. 칸보다 좁게 걷으니 너무 좁아 보여 경계를 칸 바깥으로 옮김(2026-10-19) |
| 말 외곽선 | 왕성이 잘 안 보인다는 피드백. 이웃 꼭짓점을 침범하지 않는 선에서 키우고, 말·재화 아이콘에 스티커 외곽선을 넣기로 함. 크림색 띠가 밝은 땅에서 묻혀 검은색으로 바꿈. 같은 날 검은 외곽선이 덩어리지고 거칠어 보여 사용자 결정으로 빼고 생성 원본을 그대로 씀(2026-10-19) |
| 세로 화면 | 가로로 만들던 화면을 세로형으로 바꿈. 판 크기는 그대로 두고 화면 배치만 바꿈. 로그인·프로필 카드·튜토리얼·메인 화면·매칭·턴 연출로 이어지는 흐름을 설계서 10장에 기록 |

## 타이틀 화면 선택

광산을 복원하고 전사냥·냥살자가 양쪽에서 맞서며 법사냥이 중앙 위에서 견제하는 마지막 시안을 선택했습니다. 시작 문구는 **TOUCH TO START**, 실제 UI 폰트는 **Pretendard**를 사용합니다. 원본 경로와 미리보기, 인트로 구상은 게임 설계서에서 관리합니다. 실제 Pretendard와 코드 모션을 적용했습니다. 연출용으로 하늘·지형·왕성·캐릭터 3종·로고를 분리했으며, 시작 문구는 코드로 표시합니다.

## 최신 규칙으로 바뀐 부분

| 과거 제안 | 현재 기준 |
|---|---|
| 마을은 영토만 넓히고 수급 효과 없음 | 마을을 포함한 모든 건물이 접한 타일의 자원·효과를 받음 |
| 성이 주변 3칸 거리의 효과를 받음 | 성의 꼭짓점에 접한 최대 세 타일을 수급 |
| 유닛은 이동 또는 행동 중 하나만 선택 | 이동과 공격을 각각 1회 사용하거나, 둘 대신 스킬 사용 |
| 공격 뒤 상대 거점을 점령하는 제안 | 건물 피격·파괴를 중심으로 정리. 소유권 전환은 현재 규칙에 포함하지 않음 |
| 모든 건물이 두 번 피격하면 파괴 | 왕성은 별도 체력 사용 |

## 바로잡은 내용과 주의할 점

- **숫자:** 1~12 배치는 2~12로 수정. 주사위 두 개의 합에는 1이 나오지 않음.
- **카탄 기억:** 카탄도 길만으로 자원을 받지 않음. 마을·도시가 타일에 접해야 수급함.
- **초기 배치:** 성과 마을을 같은 꼭짓점에 놓을 수 없어, 두 변 간격과 무료 길 2개로 정리함.
- **회복 시점:** 남의 턴에도 마나를 회복하면 인원수에 따라 행동량이 늘어남. 자기 턴 시작에만 회복하도록 채택함.
- **도발:** 강제 이동 뒤 명령을 허용함. 도발이 상대 턴 전체를 빼앗는 판정으로 바뀌지 않게 함.
- **은신:** 시야·탐지·공격 범위를 구분함. 법사의 공격 사각이 탐지 사각으로 자동 적용되지는 않음.
- **자동공격:** 주사위 효과 뒤, 카드 사용 전에 1회. 새 타워가 설치 즉시 공격하지 않음.
- **왕성 지원:** 연결된 먼 건물 전체가 아니라, 최단 두 변 안의 정상 연결 건물로 강화 조건을 제한함.
- **문서 상태:** 최초 문서화에서 보완한 보유 상한 공식·소환 대기·카드 순환·첫 시험 조건은 임시로 표시함. 수치 검증은 하지 않음.
- **알파 자르기 요청:** 그림 요청문에 "알파 0 또는 255"를 넣어 디자이너가 가장자리 반투명을 없앴고, 외곽선이 계단처럼 거칠어졌음. 이후 요청문은 "안쪽 불투명, 가장자리 1~2px 부드럽게"로 씀.
- **배치 확대:** 캐릭터와 성을 키우자 광산·수정산·성이 가려졌음. 키울 때 가려지는 비율을 재지 않았기 때문. 다음에는 배치를 키울 때 가려지는 비율을 먼저 잼.

## 채택하지 않았거나 아직 정하지 않은 것

- 초기 테마 후보와 동네 아지트 설정은 최종 세계관이 아님.
- 추가 전투 주사위, 자원 이름과 수량은 미정. 종족 덱·필드 덱 구성은 [카드 목록](cards.md)의 제안 단계.
- 대마법냥의 덩어리 공격 모양, 육각판 뒤쪽 판정, 도약공격의 행동 분류는 미정.
- 최종 게임 플랫폼·UI와 맵 디자인은 미정. 화면 방향은 2026-10-18에 세로로 정함. 첫 구현은 브라우저에서 확인하도록 Vite와 자바스크립트를 사용. 캐릭터 그림체는 메인 콘셉트 세 장을 기준으로 하며, 다른 프로젝트의 결정을 가져오지 않음.

## 이번 구현의 범위

- 약 2.7초 인트로: 하늘 → 동산·앞쪽 언덕 → 뒷산 → 광산·나무·수정산·왕성이 앞쪽 언덕 뒤에서 상승 → 전사·냥살자 돌진 → 법사 → 로고 → 시작 문구. 시간과 순서의 기준은 게임 설계서.
- 클릭·터치·Enter/Space로 시작. 연출 중 화면 터치·Enter/Space는 건너뛰기만 하고 시작하지 않음.
- 다시 보기, 모션 줄이기 설정, 이미지 실패 시 재시도 제공. 시작하면 냥국 선택 화면으로 이동.
- `assets/title/layout.json`을 화면 배치의 기준으로 사용. 지형을 가로로 잘라 쓰던 방식은 제거하고 동산·뒷산·광산·수정산을 별도 PNG로 제작. 현재 구성은 아래 ‘타이틀 재구성’ 참고.
- Vite·Sharp·Playwright·Pretendard를 사용. 인트로는 Web Animations API로 처리하고 종료 뒤 해제. 대기 반복 연출 둘(시작 문구·법사 부유)은 CSS로 처리하며 transform·opacity만 사용.
- Ponytail 공식 스킬과 MIT 라이선스를 저장소에 포함. 플러그인 자동 설치나 전역 설정 변경은 하지 않았으며, 프로젝트 지침에서 스킬을 연결.
- 최종 플랫폼과 세로 전용 구도는 미정. 현재 타이틀은 가운데 4:3 안전 영역이 항상 보이게 맞춤.

## 냥국 선택과 시작 순서

- 타이틀 → 플레이어 1 선택 → 플레이어 2 선택 → 시작 순서 주사위 → 준비 완료로 연결.
- 기존 세 캐릭터 WebP를 재사용. 상성·주요 능력·주의할 상대를 짧게 표시. 같은 클래스 선택 허용은 임시 시험 규칙.
- 선택 전 완료 버튼과 차례가 아닌 주사위 버튼은 잠금. 이미 굴린 주사위를 다시 굴릴 수 없음.
- 시작 주사위는 나온 눈을 제외해 뽑음. 동점만 다시 굴릴 때와 같은 확률이며, 큰 숫자부터 첫 배치. 자원 수급용 주사위에는 적용하지 않음.
- 보기만 하고 돌아오면 숫자를 유지. 클래스를 바꾸면 선택 확인과 두 주사위를 다시 준비. 타이틀 복귀는 선택 유지, ‘처음부터’는 초기화.
- 준비 완료 시 `setup:ready` 이벤트에 두 클래스·주사위·배치 순서를 전달. 첫 배치 지도와 실제 전투는 아직 없음.
- 규칙을 화면과 분리해 Node 규칙 검사 7개 통과. 화면 연결용 Playwright 검사도 갱신했으나, 현재 Sites 환경에서 실행하지 않음. Safari 실기기 화면 검증은 남아 있음.
- 새 라이브러리 없이 구현. 기존 이미지 URL을 재사용해 추가 그림을 받지 않음. 부분 글꼴은 모든 화면의 소스에서 글자를 모으도록 수정. 배포용 JS gzip 약 5.2KB, 폰트 약 48KB.

## 인트로가 보이지 않는 문제

- 증상: Safari에서 움직임 없이 완성된 타이틀만 보인다는 보고.
- 확인한 코드 문제: `prefers-reduced-motion`이 켜지면 자동 재생과 ‘다시 보기’ 모두 완성 화면으로 바로 넘어갔음. 실제 기기의 설정값은 확인하지 못함.
- 수정: 자동 연출은 큰 이동 없이 레이어를 차례로 표시. 직접 누른 ‘연출 다시 보기’는 전체 동작 재생. 줄인 연출에는 이유와 재생 방법을 표시.
- 화면이 뒤에 떠 있으면 연출을 멈추고, 다시 보일 때 이어서 재생. 끝난 연출이나 냥국 선택 화면은 자동으로 다시 시작하지 않음.
- 회귀 검사 5개 추가, 기존 선택 규칙 7개와 함께 통과. 브라우저 회귀 검사도 추가했으며 Safari 실기기 재현 확인은 아직 남아 있음.
- 교훈: 접근성 설정으로 자동 움직임을 줄여도, 사용자가 누른 재생 버튼까지 아무 설명 없이 무시하지 않기.

## 지형 분리와 연출 재조정

- 광산·수정산의 잘림은 한 지형 그림을 가로 영역으로 나눠 움직이던 방식 때문. 새 PNG 4장으로 교체하고 성도 다시 그림. 원본 시안과 이전 지형은 보관.
- 성은 참고 사진의 일반적인 탑·성벽·문 구성을 새 그림으로 해석. 사진 자체는 저장소에 넣지 않음. 큰 깃발 한 개에 발바닥 문양을 넣음.
- 처음은 기기의 ‘동작 줄이기’를 따름. 직접 다시 보기는 전체 동작을 재생하고 선택을 저장(이후 저장하지 않도록 고침). 화면에서 전체/줄임 전환 가능. 기기 성능에 따른 자동 생략 기능은 없음. iPad mini 5의 실제 설정과 재현 원인은 아직 확인하지 못함.
- 배치 정보는 캐시 없이 가져오고 각 이미지 내용의 식별값을 URL에 붙임. 바뀐 그림과 예전 캐시의 혼용을 줄임(이후 배치를 빌드에 포함하도록 바꿈).
- 대기 반복 연출은 설계서에 미정 제안으로 정리(이후 두 가지를 임시로 채택). 이때는 인트로가 끝나면 애니메이션을 해제하고 GPU 힌트도 제거.
- 이번 확인: Node 검사 13개, 배포용 빌드, 웹앱 설정 검사 통과. 브라우저용 검사 16개 목록 갱신. 미리보기는 서버가 실행됐으나 검증 브라우저가 접속을 차단하여 브라우저 검사·Safari 실기기 재생은 미검증. 아트 조합 이미지를 눈으로 확인함.
- 타이틀 원본 10장 약 9.52MB → 실행 이미지 약 0.62MB. 부분 글꼴 약 48.9KB, JS gzip 약 5.7KB. 실제 기기의 프레임 속도는 측정하지 않음.

## 타이틀 재구성

**이유**

- 캐릭터가 광산·수정산·성을 가렸음.
- 등장 중 반투명한 잔상이 보였음.
- 움직임이 한 번 멈췄다가 다시 시작했음.
- 4:3 화면에 위아래 띠가 생겼음.
- 다시 보기가 움직임 설정을 저장했음. 한 번 보는 버튼이라 잘못이었음.

## 저사양 기기 기준 정리

기준 기기를 iPad mini 5로 정함. 메모리가 작고 CPU가 오래된 이 기기에서도 끊김·발열 없이 도는 것이 핵심 목표. 기준은 [작업 지침](../AGENTS.md)에 기록.

| 항목 | 바꾼 것과 이유 |
|---|---|
| 화면 흔들림 | 제거. 흔들림은 과한 연출로 보고 권장안을 채택. 인트로 길이(2.7초)는 그대로 |
| 대기 연출 | 끝없는 반복을 횟수 제한으로 바꿈. 타이틀에 머무는 동안 화면을 계속 다시 그려 저사양 기기에 열이 날 수 있었음. 2026-10-19에 사용자가 살아 있는 느낌의 반복 연출을 원해, 캐릭터별 대기 연출을 약 74초 반복한 뒤 쉬는 자세에서 멈추는 절충안으로 넣음 |
| 그림 중복 받기 | 선택 화면이 타이틀 그림을 식별값 없는 주소로 불러 3장을 두 번 받았음(약 0.27MB). 식별값을 붙인 같은 주소를 쓰도록 고침. 처음 기록의 ‘기존 이미지 URL 재사용’이 식별값 추가 뒤 깨졌던 것 |
| 윈도우 빌드 | `npm run assets`가 윈도우에서 저장 경로를 `/E:/…` 모양으로 넘겨 실패했음. `fileURLToPath`로 고침. 맥·리눅스에서만 시험해서 드러나지 않았음 |

확인: 규칙 검사 12개(흔들림 검사 삭제), 브라우저 검사 18개(중복 받기 검사 추가)를 Chromium과 WebKit에서 실행. 실기기 확인은 여전히 남아 있음.

## 판 크기와 시작 자리 검사

모드별 판 크기는 "한 명당 육지 약 80칸"에서 출발했습니다. 시작 자리 규칙이 늘 성립하는지 무작위 판을 모드마다 1000개씩 만들어 확인했습니다. 결과는 게임 설계서의 시작 자리 규칙 표에 있습니다.

| 항목 | 내용 |
|---|---|
| 검사 판 | 4:3 상자 안의 타원 대륙. 해안선은 칸마다 흔들고 가장 큰 덩어리만 남김. 지형은 설계서 비율대로 칸마다 무작위 |
| 고른 거리 | 1대1 12칸 이상은 1000판 중 4판 실패. 4인 11칸 이상은 17판 실패. 실패 없는 가장 먼 값으로 10칸을 고름 |
| 팀전 | 팀원 거리에 상한이 없으면 최대 15칸까지 벌어져 서로 돕기 어려움. 11칸 상한을 넣어도 실패 0 |
| 한계 | 실제 생성기는 지형을 덩어리로 묶고 수정을 가운데에 모을 예정. 생성기를 만든 뒤 같은 검사를 다시 함 |

같은 날 바닥 타일 4종(PR #6)을 검수했습니다. 정육각형이 코드의 칸과 맞고, 타일 한 장에 9~13색만 써서 노이즈 정리가 필요 없습니다. 테두리와 옆면 사이의 1px 잔점은 게임 크기에서 보이지 않아 그대로 둡니다.

## 세로 전환과 판 만들기 (4단계 1차)

iPad에서 설계를 확인할 수 있게 만든 1차입니다. 판 생성은 Sonnet, 화면은 Opus 에이전트가 만들고 지휘 쪽이 검수했습니다.

| 항목 | 내용 |
|---|---|
| 판 생성 | `board.js`: 모드별 대륙(타원 + 부드러운 잡음, 가장 큰 덩어리, 안쪽 바다 메움), 지형 덩어리(2~4칸), 수정산 가운데 쏠림, 호수·바위산이 길을 끊으면 그 덩어리만 다시 놓음, 시작 자리 규칙. 무작위 판 1000개씩 실패 0, 4인 판 생성 평균 약 2~5ms(PC) |
| 들어가는 길 | 타이틀 → 임시 대전 방식 선택(1대1 / 4인 → 개인전·팀전) → 판. 판 아래 **모드 바꾸기**(임시)로 돌아감. 예전 2인 선택 화면과 그 검사는 지움 |
| 그리기 | 바닥 타일 WebP 600px 4종(합계 약 66KB). 줄인 그림 단계(300·150·75·38px)를 한 번 만들어 필요한 크기 이상 가장 작은 단계를 씀. 화면 밖 칸은 그리지 않음. 칸이 작으면(반지름 22px 미만) 숫자 패를 숨김. 그림이 늦거나 실패해도 지형 색 칸으로 대신 그리고 다시 불러오기 버튼을 보임 |
| 세로 배치 | 왼쪽 위 프로필·상대(팀전은 같은 팀·상대 팀), 오른쪽 위 재화, 왼쪽 아래 미니맵, 오른쪽 아래 카드. 가로로 돌리면 가운데 세로 기둥 |
| 측정 | Chromium, CPU 6배 느림, 2배 화면, 768×1024, 4인 판: 전체 보기(312~315칸) 평균 2.3~3.0ms·최대 7.1ms, 최대 확대(36칸) 평균 0.3~1.3ms·최대 16.4ms(처음 큰 그림을 쓸 때 한 번). 실제 픽셀 그리기 시간은 빠진 값 |
| 지휘 쪽 수정 | 지형을 놓을 곳을 끝내 못 찾을 때 판 생성이 멈추지 않게 시도 횟수 상한을 넣음 |

확인하지 못한 것: iPad 실기기의 그리기 시간·발열·손맛, 가로 휴대폰(기둥 폭 약 292px)에서 HUD가 빽빽한지.

## 세로 타이틀과 지도 그림 (4단계 2차)

디자이너 PR #8(지형)·#9(게임 진행용)·#10(세로 타이틀)을 검수해 합치고, 두 Opus 에이전트가 차례로 반영했습니다(같은 검사 서버와 빌드 폴더를 써서 동시에 돌리지 않음). 디자이너 첫 세로 시안 PR #7과 기존 그림으로 조립한 A~D 안은 사용자가 모두 고르지 않아 닫았습니다.

| 항목 | 내용 |
|---|---|
| 타이틀 | 정면 전사 중심의 세로 3:4 배치. 긴 폰은 하늘·땅이 이어지고, 넓은 창은 가운데 기둥. 인트로 순서를 새로 짬 |
| 타이틀 용량 | 넓은 지형 층을 0.5배로 내보냄(1배와 비교해 차이 없음). 실행 그림 0.65 → 0.41MB, 첫 로딩 약 0.72 → 0.49MB, 펼친 그림 메모리 약 27 → 19MiB |
| 지휘 쪽 수정 | 뒷산 아래끝이 평평해 인트로 중 잘린 선으로 보였음. 뒷산을 내리고 조금 늘려 언덕 뒤로 숨김. 판 전체 보기에서 성을 찾기 어려워 플레이어 색 받침을 깖 |
| 지도 그림 | 오브젝트 4종·호수·성(플레이어 색)·재화 아이콘·카드 뒷면 적용. 새 용량 약 87KB, 시작을 누를 때 미리 받는 양 66 → 142KB, 펼친 그림 메모리 +4.5MB |
