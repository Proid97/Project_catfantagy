# 대화 맥락

갱신일: 2026-10-17 · 한국 시간

현재 단계는 **냥국 선택·시작 순서 준비 구현**입니다. 타이틀은 새 아트·구성·인트로를 적용했고, iPad mini 5 실기기 확인이 남았습니다. 게임 플레이와 밸런스 시험은 아직 하지 않았습니다. 현재 규칙은 [게임 설계](game-design.md), 작성 방법은 [작업 지침](../AGENTS.md)을 따릅니다.

## 결정의 흐름

| 순서 | 결정과 이유 |
|---|---|
| 출발 | 카탄의 주사위 자원 수급, 스타크래프트처럼 자원을 써 건물·유닛 배치, 무작위 카드 드로우를 결합하고자 함 |
| 콘셉트 탐색 | 냉장고·꿈·축제·고양이 등 여러 테마를 검토. 대중적으로 이해하기 쉬운 고양이 방향을 선호 |
| 최종 방향 | 동네 고양이에서 클래식 판타지 ‘냥국’으로 변경. 가칭은 운빨냥국배틀 |
| 운의 역할 | 시작 땅까지 안개로 가림. 주사위 수입과 카드 드로우에서 생기는 큰 운을 주요 재미로 삼음 |
| 클래스 | 냥전사·냥법사·냥살자가 서로 카운터가 되도록 설계. 은신 기습·높은 체력과 도발·넓은 공격 범위로 차별화 |
| 기본 판 | 육각 타일, 꼭짓점 건물, 변 위 길로 구체화. 모든 건물에 주변 타일 수급권 부여 |
| 행동 | 이동과 공격은 각각 턴당 1회, 스킬은 해당 유닛의 한 턴을 사용. 마나는 별도로 소모 |
| 공성 | 일반 건물은 두 번 피격하면 파괴. 왕성은 체력과 자동공격을 갖고 주변 정상 지원 건물에 따라 공격력이 바뀜 |
| 문서화 | 사용자가 남은 사항에 권장안 적용을 요청. 채택한 규칙과 새로 메운 임시 판정을 구분해 최초 기록 |
| 제작·관리 | 아트는 ChatGPT 이미지젠. 쉬운 한국어, 짧은 구성, 지속 가능한 파일명, 같은 분류는 같은 문서에서 갱신 |
| 아트 방식 | 피규어·종이 스탠드·토큰 모크업을 비교한 뒤 토큰 선택. 팔다리 애니메이션 없이 말 전체를 코드로 움직이고 마법 효과도 코드·이미지로 처리 |
| 디자인 상태 | 플레이 화면의 세부 디자인은 추후 변경. 캐릭터는 색·실루엣·자세를 다르게 수정한 세 이미지를 메인 콘셉트로 선택 |
| 메인 콘셉트 | 냥살자, 주황·금색 전사냥, 흰색·보라색 법사냥. 법사냥은 마지막 수정 과정의 세 번째 이미지. 경로와 미리보기는 게임 설계서에서 관리 |

## 타이틀 화면 선택

광산을 복원하고 전사냥·냥살자가 양쪽에서 맞서며 법사냥이 중앙 위에서 견제하는 마지막 시안을 선택했습니다. 시작 문구는 **TOUCH TO START**, 실제 UI 폰트는 **Pretendard**를 사용합니다. 원본 경로와 미리보기, 인트로 구상은 게임 설계서에서 관리합니다. 실제 Pretendard와 코드 모션을 적용했습니다. 연출용으로 하늘·지형·왕성·캐릭터 3종·로고를 분리했으며, 시작 문구는 코드로 표시합니다.

## 최신 규칙으로 바뀐 부분

| 과거 제안 | 현재 기준 |
|---|---|
| 마을은 영토만 넓히고 수급 효과 없음 | 마을을 포함한 모든 건물이 접한 타일의 자원·효과를 받음 |
| 성이 주변 3칸 거리의 효과를 받음 | 성의 꼭짓점에 접한 최대 세 타일을 수급 |
| 유닛은 이동 또는 행동 중 하나만 선택 | 이동과 공격을 각각 1회 사용하거나, 둘 대신 스킬 사용 |
| 공격 뒤 상대 거점을 점령하는 제안 | 건물 피격·파괴를 중심으로 정리. 소유권 전환은 현재 규칙에 포함하지 않음 |
| 모든 건물이 두 번 피격하면 파괴 | 왕성은 별도 체력 사용 |

## 바로잡은 내용과 주의할 점

- **숫자:** 1~12 배치는 2~12로 수정. 주사위 두 개의 합에는 1이 나오지 않음.
- **카탄 기억:** 카탄도 길만으로 자원을 받지 않음. 마을·도시가 타일에 접해야 수급함.
- **초기 배치:** 성과 마을을 같은 꼭짓점에 놓을 수 없어, 두 변 간격과 무료 길 2개로 정리함.
- **회복 시점:** 남의 턴에도 마나를 회복하면 인원수에 따라 행동량이 늘어남. 자기 턴 시작에만 회복하도록 채택함.
- **도발:** 강제 이동 뒤 명령을 허용함. 도발이 상대 턴 전체를 빼앗는 판정으로 바뀌지 않게 함.
- **은신:** 시야·탐지·공격 범위를 구분함. 법사의 공격 사각이 탐지 사각으로 자동 적용되지는 않음.
- **자동공격:** 주사위 효과 뒤, 카드 사용 전에 1회. 새 타워가 설치 즉시 공격하지 않음.
- **왕성 지원:** 연결된 먼 건물 전체가 아니라, 최단 두 변 안의 정상 연결 건물로 강화 조건을 제한함.
- **문서 상태:** 최초 문서화에서 보완한 보유 상한 공식·소환 대기·카드 순환·첫 시험 조건은 임시로 표시함. 수치 검증은 하지 않음.
- **배치 확대:** 캐릭터와 성을 키우자 광산·수정산·성이 가려졌음. 키울 때 가려지는 비율을 재지 않았기 때문. 다음에는 배치를 키울 때 가려지는 비율을 먼저 잼.

## 채택하지 않았거나 아직 정하지 않은 것

- 초기 테마 후보와 동네 아지트 설정은 최종 세계관이 아님.
- 추가 전투 주사위, 클래스별 전용 덱의 상세 구성, 자원 이름과 수량은 미정.
- 대마법냥의 덩어리 공격 모양, 육각판 뒤쪽 판정, 도약공격의 행동 분류는 미정.
- 최종 게임 플랫폼·화면 방향·UI와 맵 디자인은 미정. 첫 구현은 브라우저에서 확인하도록 Vite와 자바스크립트를 사용. 캐릭터 그림체는 메인 콘셉트 세 장을 기준으로 하며, 다른 프로젝트의 결정을 가져오지 않음.

## 개발 순서

한 단계를 직접 플레이해 확인한 뒤 다음 단계로 갑니다. 아래 순서는 개발 계획이며, 미정인 규칙을 확정한 것은 아닙니다.

| 순서 | 만들 것 | 끝났다고 보는 기준 |
|---|---|---|
| 1 · 확인 대기 | 타이틀 화면 | 새 아트·구성·인트로 적용 완료. iPad mini 5 실기기 확인 후 마무리 |
| 2 · 완료 | 냥국 선택과 게임 준비 | 두 플레이어 클래스 선택 → 시작 순서 주사위. 선택 변경·타이틀 복귀 가능 |
| 3 · 다음 | 육각판과 첫 배치 | 타일·변·꼭짓점 표시, 안개 속 왕성·마을·길 배치, 금지 자리 차단 |
| 4 | 주사위·자원·카드·턴 | 자원 종류·초기 덱·비용을 먼저 정함. 양쪽 수급, 손패 상한, 턴 종료까지 한 턴이 돌아감 |
| 5 | 건설과 전투 | 방향·착지·공격 모양·기본 수치를 먼저 정함. 이동·공격·마나·파손·왕성 파괴로 1판 종료 |
| 6 | 클래스 개성·마법·함정 | 은신·탐지·도발·범위 공격과 동시 효과 순서를 시험 |
| 7 | 봇과 밸런스 | 쉬운 봇과 반복 시험, 운과 상성을 수치로 확인, 한 판의 속도 조절 |
| 8 | 저장·설정·출시 준비 | 저장·복원, 사운드, 실제 기기 성능, 조작과 안내 다듬기. 온라인 대전은 필요와 범위를 따로 결정 |

지금은 **타이틀의 iPad mini 5 실기기 확인**을 먼저 마칩니다. 대기 움직임 중 적용하지 않은 제안은 미정으로 둡니다. 그다음은 육각판과 첫 배치입니다. 정해진 순서대로 안개 속에 왕성·마을·길을 놓습니다. 초기 시험은 한 기기에서 번갈아 하는 1대1로 만들고, 봇과 온라인은 뒤에 붙입니다. 이는 검증 순서를 위한 임시 선택입니다.

## 이번 구현의 범위

- 약 2.7초 인트로: 하늘 → 동산·앞쪽 언덕 → 뒷산 → 광산·나무·수정산·왕성이 앞쪽 언덕 뒤에서 상승 → 전사·냥살자 돌진 → 법사 → 로고 → 시작 문구. 시간과 순서의 기준은 게임 설계서.
- 클릭·터치·Enter/Space로 시작. 연출 중 화면 터치·Enter/Space는 건너뛰기만 하고 시작하지 않음.
- 다시 보기, 모션 줄이기 설정, 이미지 실패 시 재시도 제공. 시작하면 냥국 선택 화면으로 이동.
- `assets/title/layout.json`을 화면 배치의 기준으로 사용. 지형을 가로로 잘라 쓰던 방식은 제거하고 동산·뒷산·광산·수정산을 별도 PNG로 제작. 현재 구성은 아래 ‘타이틀 재구성’ 참고.
- Vite·Sharp·Playwright·Pretendard를 사용. 인트로는 Web Animations API로 처리하고 종료 뒤 해제. 대기 반복 연출 둘(시작 문구·법사 부유)은 CSS로 처리하며 transform·opacity만 사용.
- Ponytail 공식 스킬과 MIT 라이선스를 저장소에 포함. 플러그인 자동 설치나 전역 설정 변경은 하지 않았으며, 프로젝트 지침에서 스킬을 연결.
- 최종 플랫폼과 세로 전용 구도는 미정. 현재 타이틀은 가운데 4:3 안전 영역이 항상 보이게 맞춤.

## 확인 결과

- 배포용 빌드와 Chromium 자동 검증 9개 통과.
- 1672×941, 844×390, 390×844, 2560×1080에서 그림·시작 버튼 확인. 터치, 키보드, 모션 줄이기, 로딩 실패 복구 포함.
- 이미지 7장: 7.71MB → 0.80MB. Pretendard 부분 글꼴: 791KB → 41KB. 첫 로딩 리소스 전송량은 로컬 시험에서 약 0.84MB. HTML과 서버 압축·헤더 차이는 별도.
- 배포용 JS는 gzip 약 1.9KB. 인트로 종료 뒤 실행 중인 애니메이션 0개 확인.
- 자동 검증은 headless Chromium 153으로 실행. 실제 휴대폰·Safari·저사양 기기의 메모리와 프레임 속도는 아직 확인하지 않음. 이때는 웹 배포를 하지 않았으며, 이후 Safari 검증용 Sites 호스팅을 추가함.

## Safari 검증용 배포

- 주소: https://catfantagy-preview.proid6638.chatgpt.site
- 호스팅: Sites. 초기 접근 범위는 본인 계정. 기본 비공개 설정을 유지함.
- GitHub Pages 추가 선택: 무료이고 다른 계정이 필요 없음. `main`에 올리면 자동 배포. 저장소가 공개라 페이지도 공개. Sites는 이전 비공개 주소로 남김.
- 주소: https://proid97.github.io/Project_catfantagy/. 저장소 주인이 Pages Source를 **GitHub Actions**로 한 번 바꿔야 함. 연결 도구는 이 설정을 바꿀 수 없음.
- 다음은 iPad mini 5 실기기에서 이 주소를 열어 확인하는 일.
- Safari용 웹앱 매니페스트, Apple 홈 화면 이름·아이콘, 독립 실행, 안전 영역 여백 추가. 화면 방향은 잠그지 않음.
- 홈 화면 추가 방법과 검증 항목은 README에 기록. 오프라인 실행·캐시는 이번 범위에서 제외.
- GitHub 연결 도구는 Pages 설정 API를 지원하지 않아 Sites로 배포. GitHub 연결 실패나 로컬 CLI 실패로 해석하지 않음.
- 배포 전 빌드와 설정 검증 수행. 현재 환경의 Sites 지침에 따라 브라우저 QA는 실행하지 않음. 실제 iPad의 설치·실행 여부는 사용자 검증으로 확인.

## 냥국 선택과 시작 순서

- 타이틀 → 플레이어 1 선택 → 플레이어 2 선택 → 시작 순서 주사위 → 준비 완료로 연결.
- 기존 세 캐릭터 WebP를 재사용. 상성·주요 능력·주의할 상대를 짧게 표시. 같은 클래스 선택 허용은 임시 시험 규칙.
- 선택 전 완료 버튼과 차례가 아닌 주사위 버튼은 잠금. 이미 굴린 주사위를 다시 굴릴 수 없음.
- 시작 주사위는 나온 눈을 제외해 뽑음. 동점만 다시 굴릴 때와 같은 확률이며, 큰 숫자부터 첫 배치. 자원 수급용 주사위에는 적용하지 않음.
- 보기만 하고 돌아오면 숫자를 유지. 클래스를 바꾸면 선택 확인과 두 주사위를 다시 준비. 타이틀 복귀는 선택 유지, ‘처음부터’는 초기화.
- 준비 완료 시 `setup:ready` 이벤트에 두 클래스·주사위·배치 순서를 전달. 첫 배치 지도와 실제 전투는 아직 없음.
- 규칙을 화면과 분리해 Node 규칙 검사 7개 통과. 화면 연결용 Playwright 검사도 갱신했으나, 현재 Sites 환경에서 실행하지 않음. Safari 실기기 화면 검증은 남아 있음.
- 새 라이브러리 없이 구현. 기존 이미지 URL을 재사용해 추가 그림을 받지 않음. 부분 글꼴은 모든 화면의 소스에서 글자를 모으도록 수정. 배포용 JS gzip 약 5.2KB, 폰트 약 48KB.

## 인트로가 보이지 않는 문제

- 증상: Safari에서 움직임 없이 완성된 타이틀만 보인다는 보고.
- 확인한 코드 문제: `prefers-reduced-motion`이 켜지면 자동 재생과 ‘다시 보기’ 모두 완성 화면으로 바로 넘어갔음. 실제 기기의 설정값은 확인하지 못함.
- 수정: 자동 연출은 큰 이동 없이 레이어를 차례로 표시. 직접 누른 ‘연출 다시 보기’는 전체 동작 재생. 줄인 연출에는 이유와 재생 방법을 표시.
- 화면이 뒤에 떠 있으면 연출을 멈추고, 다시 보일 때 이어서 재생. 끝난 연출이나 냥국 선택 화면은 자동으로 다시 시작하지 않음.
- 회귀 검사 5개 추가, 기존 선택 규칙 7개와 함께 통과. 브라우저 회귀 검사도 추가했으며 Safari 실기기 재현 확인은 아직 남아 있음.
- 교훈: 접근성 설정으로 자동 움직임을 줄여도, 사용자가 누른 재생 버튼까지 아무 설명 없이 무시하지 않기.

## 지형 분리와 연출 재조정

- 광산·수정산의 잘림은 한 지형 그림을 가로 영역으로 나눠 움직이던 방식 때문. 새 PNG 4장으로 교체하고 성도 다시 그림. 원본 시안과 이전 지형은 보관.
- 성은 참고 사진의 일반적인 탑·성벽·문 구성을 새 그림으로 해석. 사진 자체는 저장소에 넣지 않음. 큰 깃발 한 개에 발바닥 문양을 넣음.
- 처음은 기기의 ‘동작 줄이기’를 따름. 직접 다시 보기는 전체 동작을 재생하고 선택을 저장(이후 저장하지 않도록 고침). 화면에서 전체/줄임 전환 가능. 기기 성능에 따른 자동 생략 기능은 없음. iPad mini 5의 실제 설정과 재현 원인은 아직 확인하지 못함.
- 배치 정보는 캐시 없이 가져오고 각 이미지 내용의 식별값을 URL에 붙임. 바뀐 그림과 예전 캐시의 혼용을 줄임(이후 배치를 빌드에 포함하도록 바꿈).
- 대기 반복 연출은 설계서에 미정 제안으로 정리(이후 두 가지를 임시로 채택). 이때는 인트로가 끝나면 애니메이션을 해제하고 GPU 힌트도 제거.
- 이번 확인: Node 검사 13개, 배포용 빌드, 웹앱 설정 검사 통과. 브라우저용 검사 16개 목록 갱신. 미리보기는 서버가 실행됐으나 검증 브라우저가 접속을 차단하여 브라우저 검사·Safari 실기기 재생은 미검증. 아트 조합 이미지를 눈으로 확인함.
- 타이틀 원본 10장 약 9.52MB → 실행 이미지 약 0.62MB. 부분 글꼴 약 48.9KB, JS gzip 약 5.7KB. 실제 기기의 프레임 속도는 측정하지 않음.

## 타이틀 재구성

**이유**

- 캐릭터가 광산·수정산·성을 가렸음.
- 등장 중 반투명한 잔상이 보였음.
- 움직임이 한 번 멈췄다가 다시 시작했음.
- 4:3 화면에 위아래 띠가 생겼음.
- 다시 보기가 움직임 설정을 저장했음. 한 번 보는 버튼이라 잘못이었음.

**바꾼 것** (현재 규칙은 게임 설계서)

| 항목 | 바꾼 내용 |
|---|---|
| 아트 | 원본 12종. 앞쪽 언덕(`foreground`)과 나무(`trees`) 추가, 성 지붕을 청록으로, 법사 지팡이 고리와 전사 왕관 방패를 콘셉트에 맞춤 |
| 배치 | 법사를 왼쪽 위 하늘로, 성을 약 70%로 줄여 가운데에서 조금 오른쪽으로. 법사 가운데·왼쪽·오른쪽 대칭 세 후보를 비교해 왼쪽을 택함. 성·깃발·광산·수정이 모두 보인 안이기 때문 |
| 화면 맞춤 | 4:3 안전 영역이 항상 보이게 키움. 4:3은 띠 없이 꽉 참. 남는 곳은 그림 가장자리 색 그라데이션 |
| 인트로 | 약 2.2초 → 약 2.7초. 반투명 프레임 없이 앞쪽 언덕 뒤에서 상승. 한 구간 안에서 넘쳤다 돌아오는 움직임 |
| 입력 | 연출 중 화면을 누르면 건너뛰기만 함. 다시 보기(↻)는 한 번 재생만 하고 저장하지 않음. 전체/줄임 버튼만 저장 |
| 대기 연출 | 시작 문구 밝기·법사 부유를 임시로 채택. 나머지 제안은 미정 |
| 최적화 | 배치를 빌드 때 JS에 포함(배치 파일 요청 없음). 캐시 식별값을 결과 WebP 해시로 바꿈. 하늘·동산·앞쪽 언덕을 내용 크기로 자름. 비율 유지 층은 상자의 1.75배로 내보내 4:3 iPad에서 선명하게 함. `will-change` 제거 |

**측정** (Chromium에서만 잼)

| 항목 | 값 |
|---|---|
| 실행 이미지 | WebP 13장, 합계 0.67MB |
| 디코드된 비트맵 | 약 27.8MiB (이전 30.2MiB) |
| JS gzip | 약 6.7KB |
| 글꼴 | 약 49KB |
| 첫 로딩 | 약 0.75MB |
| 자동 검사 | 규칙 13개, 브라우저 17개 통과 |

**확인하지 못한 것**

- 실제 iPad mini 5 Safari에서의 재생과 4:3 맞춤.
- 실제 기기의 메모리 사용과 프레임 속도.
